## Automation Versus Manual Trust

| Tracking method | Where it increases accuracy | Where it can create noise | What reviewers should verify |
|---|---|---|---|
| Automatic activity tracking | Captures work sessions with less dependence on memory or repeated timer starts | Keyboard and mouse activity may not reflect calls, reading, planning, or offline work | Confirm that schedules, devices, and activity categories match the team's actual workflow |
| Manual timers | Gives users direct control over task and project context | Users may forget to start, stop, or switch timers | Check notes, task assignments, and unusual time blocks before billing or approval |
| Attendance entries | Provides explicit start, end, break, and absence records | Clock events can differ from actual productive computer time | Compare attendance with activity records, leave records, and approved schedule exceptions |
| Integrations | Connects time with project management, payroll, or billing systems | Sync errors or mismatched task names can move time into the wrong category | Validate project mappings, permissions, and export rules before relying on totals |
| Retrospective edits | Allows correction of meetings, travel, offline work, and missed project switches | Late edits can reduce confidence if they lack notes or approval | Review audit history, edit reasons, and manager approval status |
| Screenshot review | Adds visual context for disputed sessions or compliance-sensitive work | Screenshots may capture unnecessary private or confidential details | Confirm screenshot policy, access limits, retention period, and relevance before review |
| Productivity categories | Helps classify apps and websites into productive, neutral, or unproductive groups | Generic categories may misclassify research, testing, or support work | Adjust categories by role, project, and business context before drawing conclusions |
